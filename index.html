태상규

Client Developer · 구조와 자동화로 비효율을 해결합니다
개발 방식 · AI 멀티 에이전트 협업

실무에서 다져온 코드 구조를 룰과 인프라 패키지로 옮기고,
AI 가 그 안에서 개발을 자동화하게 했습니다.

역할이 분리된 6개 AI 에이전트가 기획 → 리뷰 → 구현 → 검토 → 테스트 → 밸런스 검증을 분담합니다. 메인 AI 는 조율만 하고 직접 코드를 짜지 않으며, 최종 커밋은 항상 사람이 합니다. 룰을 위반한 산출물은 리뷰 에이전트가 차단합니다.

01

6개의 전담 에이전트

에이전트마다 권한과 책임을 좁게 고정했습니다. 기획자는 코드를, 구현자는 밸런스를 건드리지 않습니다.

game-designer기획

콘텐츠 기획 · 밸런스 수치 · 페이싱 설계. 코드 작성 금지.

design-reviewer읽기 전용

사용자 리뷰 전 기획서를 1차 검토. 논리 구멍·범위 이탈을 차단합니다.

gameplay-programmer구현

기획서 기반 C# 구현. .cs 파일은 전부 이 에이전트만 다룹니다.

code-reviewer읽기 전용

코딩 룰 준수 + 기획서 일치를 검토. 위반은 BLOCKER 로 되돌립니다.

test-engineer테스트

EditMode / PlayMode 테스트 스위트. 게임 로직은 작성하지 않습니다.

qa-simulator밸런스

헤드리스 시뮬레이션으로 N판 자동 플레이 후 밸런스 검증 보고서를 작성합니다.

02

작업 규모에 맞는 파이프라인 선택

위 에이전트들이 단방향으로 협업합니다. 모든 작업에 전체 흐름을 돌리지 않고, 작업 규모에 맞춰 거치는 단계가 다른 스킬 4가지를 정의해 두었습니다. 각 단계 점은 담당 에이전트 색상과 같습니다.

🙋

작업 요청이 들어오면 메인 AI 가 임의로 고르지 않습니다. 후보 스킬을 제시하고 사람이 작업 규모에 맞는 스킬을 선택할 때까지 멈춥니다 — 파이프라인 깊이 자체가 사람의 결정입니다.

03

명문화된 코딩 룰 5개

.claude/rules/ 에 명시해 AI 산출물을 통제합니다. 위반은 리뷰 에이전트가 차단하고,
최종 커밋은 항상 사람이 합니다.

Rule 00
프로젝트 메타 파일
에이전트가 프로젝트를 인지하는 단일 진입점.
Rule 01
자동 커밋 금지
AI 는 스테이징 + 커밋 메시지(안)까지만. 최종 커밋은 사람.
Rule 02
C# 스타일
주석·네이밍 규칙 + MVVM + 클래스 종속성 최소화.
Rule 03
인프라 패키지 사용 강제
풀링 · Enum 키 리소스 로드 · UI 래퍼. 중복 구현 금지.
Rule 04
Unity 에셋 규칙
프리팹화 · 타입별 폴더 구조 · Addressables 일원화.
04

직접 설계한 공용 인프라 패키지

AI 코드도 중복 구현 없이 이 패키지의 API 만 호출하도록 강제했습니다 (Rule 03).

com.chvj.unityinfra (추가 기능 필요 시 지속적으로 추가 중)

리소스 · 풀 · UI · 사운드부터 광고 · 결제 · 소셜까지 한곳에 묶은 기준 토대.
