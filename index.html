태상규

Client Developer · 구조와 자동화로 비효율을 해결합니다
개발 방식 · AI 멀티 에이전트 협업

실무에서 다져온 코드 구조를 룰과 인프라 패키지로 옮기고,
AI 가 그 안에서 개발을 자동화하게 했습니다.

역할이 분리된 6개 AI 에이전트가 기획 → 리뷰 → 구현 → 검토 → 테스트 → 밸런스 검증을 분담합니다. 메인 AI 는 조율만 하고 직접 코드를 짜지 않으며, 최종 커밋은 항상 사람이 합니다. 룰을 위반한 산출물은 리뷰 에이전트가 차단합니다. 이 체계를 Unity 와 Unreal 두 프로젝트에서 함께 쓰고 있습니다. 에이전트 구성 · 파이프라인 · 정기 루틴은 동일하고, 엔진에 따라 갈리는 04 룰 · 05 인프라 · 06 에디터는 각 섹션에서 전환해 보실 수 있습니다.

01

6개의 전담 에이전트

에이전트마다 권한과 책임을 좁게 고정했습니다. 기획자는 코드를, 구현자는 밸런스를 건드리지 않습니다. 두 엔진 프로젝트가 같은 역할 분리를 씁니다.

game-designer기획

콘텐츠 기획 · 밸런스 수치 · 페이싱 설계. 코드 작성 금지. UI 기획이면 HTML 목업까지 함께 냅니다.

design-reviewer읽기 전용

사용자 리뷰 전 기획서를 1차 검토. 논리 구멍·범위 이탈을 차단합니다.

gameplay-programmer구현

기획서 기반 구현. 구현 파일은 전부 이 에이전트만 다룹니다.

Unity .cs · Unreal .h / .cpp
code-reviewer읽기 전용

코딩 룰 준수 + 기획서 일치를 검토. 위반은 BLOCKER 로 되돌립니다.

test-engineer테스트

자동화 테스트 스위트 작성. 게임 로직은 작성하지 않습니다.

Unity EditMode / PlayMode · Unreal Automation
qa-simulator밸런스

헤드리스 시뮬레이션으로 N판 자동 플레이 후 밸런스 검증 보고서를 작성합니다.

02

작업 규모에 맞는 파이프라인 선택

위 에이전트들이 단방향으로 협업합니다. 모든 작업에 전체 흐름을 돌리지 않고, 작업 규모에 맞춰 거치는 단계가 다른 스킬 4가지를 정의해 두었습니다. 두 엔진 프로젝트가 이 4개 스킬을 이름·순서까지 동일하게 공유합니다.

🙋

작업 요청이 들어오면 메인 AI 가 임의로 고르지 않습니다. 후보 스킬을 제시하고 사람이 작업 규모에 맞는 스킬을 선택할 때까지 멈춥니다 — 파이프라인 깊이 자체가 사람의 결정입니다.

03

정기 자동화 루틴

에이전트가 요청받을 때만 일하지 않습니다. 일간·주간 스케줄로 백그라운드에서 기획 인풋을 만들어 git 에 올리고, 산출물은 초안일 뿐 사람이 확인해 반영합니다.

idea-backlog일간

💡 추가 기획 아이디어 정리 — 신규 콘텐츠·기능 기획거리를 모아 백로그 문서로 정리합니다.

reference-research주간

🔍 레퍼런스 게임 리서치 — 레퍼런스·경쟁 게임을 점검해 비교·분석 문서를 갱신합니다.

🔄 매 실행마다 자동 git 푸시 ✅ 반영은 항상 사람이 루틴은 초안을 올리고, 사람이 확인해 추가·업데이트합니다.

명문화된 코딩 룰 5개

05

직접 설계한 공용 인프라

AI 코드도 중복 구현 없이 이 계층의 API 만 호출하도록 강제했습니다 (Rule 03).

com.chvj.unityinfra (Packages/ — 추가 기능 필요 시 지속적으로 추가 중)

리소스 · 풀 · UI · 사운드부터 광고 · 결제 · 소셜까지 한곳에 묶은 기준 토대.

Core싱글톤 · 공용 유틸 · SDK 진입점

Pool오브젝트 풀링

Ads광고 연동

의존성 방향: Assets/ (게임 코드) → com.chvj.unityinfra → Unity 표준 패키지 (역방향 참조 금지)
재사용 플러그인 4종 (Plugins/ — 프로젝트 비의존, 게임 모듈과 분리)

엔진 위에 한 겹을 더 올려, 게임 모듈이 엔진 API 를 직접 만지지 않게 했습니다.

의존성 방향: 게임 모듈 → SK 플러그인 → 엔진 GAS / UMG (역방향 참조 금지)
06

코드를 넘어 에디터까지

게임 작업의 절반은 에디터 안에 있습니다. AI 가 코드만 쓰고 멈추지 않도록 두 엔진 모두 MCP 서버로 에디터를 직접 조작하게 하고, 대신 안전장치를 걸었습니다.

🖼️

목업 승인 게이트는 두 엔진 공통입니다. 화면 배치를 만들거나 바꾸는 작업은, 먼저 목업을 사람에게 보여 승인받기 전까지 실제 UI 배선에 착수하지 못합니다. 메인 AI 가 "이 정도는 목업 없이" 라고 임의 판단하지 않습니다.

UnityMCP에디터 제어

🎛️ 프리팹·씬을 AI 가 직접 — 프리팹 열기·저장 · 씬 오브젝트 생성 · 컴포넌트 부착과 프로퍼티 설정을 MCP 서버로 수행합니다.
